# 王金武乱斗 13.0 · 大厅、关卡与账号云存档

## 本次更新
- 横屏游戏大厅重新整理：左侧竖向导航、顶部玩家信息/货币/账号区、中间角色展示、右侧快速开战区。角色展示缩小并限制在自己的展示框内，不遮挡文字和按钮。
- 单人模式改为 20 关闯关制：关卡地图、解锁状态、通关标记、逐关难度、敌人数量/生命、击败目标、限时和金币奖励。通关后自动解锁下一关。
- 增加用户名+密码注册/登录窗口，连接现有 Supabase Edge Function `username-auth`。用户名 3–20 位小写字母/数字/下划线，密码 8–72 位。
- 登录后自动读取云存档；游戏存档变更后自动同步。保存金币、钻石、角色、皮肤、武器、背包、关卡进度、战绩、签到和设置。支持退出后重新登录恢复。
- 账号密码不会保存在游戏存档中；前端仅保存 Supabase 登录会话。客户端只使用公开 Publishable Key，不包含 Service Role/Secret Key。

## 必须做一次的 Supabase 设置
1. 打开 Supabase 项目 Dashboard。
2. 进入 SQL Editor。
3. 打开本目录的 `supabase_game_saves.sql`，复制全部 SQL 并执行一次。它会创建 `public.game_saves` 云存档表并开启 RLS，只允许登录用户读写自己的那一行。
4. 确认原有 Edge Function `username-auth` 仍处于部署状态，且按 `{action:"register"|"login", username, password, nickname?}` 接收请求、返回 `{success:true,user,session}`。
5. 重新打开游戏，注册或登录账号。

## 新手奖励
新账号初始化游戏云存档时显示 1000 金币和 100 钻石。账号认证服务原有的一次性奖励逻辑仍由服务端负责；不要在客户端添加 Service Role Key 或直接修改受保护的玩家表。

## 运行方式
1. 解压 ZIP，保持 `index.html`、`assets/` 和 SQL 文件在原有目录结构。
2. 用 HTTPS 静态站点或本地静态服务器打开 `index.html`。账号认证和云存档需要联网。
3. 建议手机横屏体验。

## 功能边界
- 单人关卡可本地运行；游戏内单人进度会同步到账号云存档。
- 好友房间仍需要部署匹配的 WebSocket 服务器；本 ZIP 不包含联机服务器。
- 第一次为账号创建云存档前，会把当前设备的本地存档迁移到该账号；设备记录了其他账号归属时，不会把前一个账号的数据上传给新账号。


## V13.2 优化内容
- 单人关卡开局只生成 1 名普通敌人，之后按间隔分批刷新，限制同时在场敌人数。
- 最后一名目标敌人后出现关底精英，敌人不再无限复活。
- 降低前期 AI 追击速度、射击频率和子弹速度，提升新手生存空间。
- 角色技能区分为冲击、冲刺、护盾、治疗、影袭、电磁脉冲、奥术过载，并加入冷却。
- 大厅功能入口改为居中弹窗式页面，支持关闭按钮、点击遮罩和 Esc 关闭。
- 横屏触控按钮调整为攻击主按钮、技能次按钮、炸弹辅助按钮，炸弹和技能改为单次点击触发。

## V13.7 好友、礼物与羁绊系统
- 新增好友入口：按唯一用户名发送申请、接受/拒绝申请、好友列表和亲密值显示。
- 六种礼物：糖果（50 金币/+2）、鲜花（200 金币/+10）、蛋糕（500 金币/+30）、星钻（50 钻石/+80）、梦幻花束（200 钻石/+250）、王者皇冠（500 钻石/+700）。
- 亲密值为双方共享累计值；达到 1000 后，双方都发起羁绊申请才会绑定「羁绊搭档」。
- 礼物扣费、亲密值变更和好友关系由 Supabase RPC 在数据库事务中完成；客户端不允许直接写好友表。
- 首次启用需在 Supabase SQL Editor 执行 `supabase_friends_gifts.sql`。该迁移会创建好友申请、好友关系和礼物流水表及安全 RPC。保留原有 `supabase_game_saves.sql` 和 `username-auth`，不要删除旧表。
- 用户名查找依赖 `username-auth` 注册时写入 `auth.users.raw_user_meta_data.username`；若现有 Edge Function 未写入该字段，需先调整服务端注册逻辑，否则好友搜索无法按用户名定位。
